# LoveVerse V4 · Love Companion 架构

## 增量集成

从 V3 提交 082e1f8 的干净工作区创建 `codex/v4-love-companion`，审查并合并用户提供的 14 文件 ZIP。没有重新创建项目、覆盖用户修改或导入数据。包内旧验证记录已由本机实测报告替代。

新增 `#companion`，沿用现有星空、居中容器、Hash 导航、MemoryProvider、原生 dialog 和照片详情。公开模式只展示说明；V4 API 仍完全关闭。私人功能需要应用账号，未沿用公开 AI 的免登录例外。

## 服务与数据

- `src/lib/v4/model.ts`：动作联合 Schema、章节、草稿、胶囊、提醒和通知。
- `store.ts`：`private/state/loveverse-v4.json`，最大 8MB。复用安全路径、锁、临时文件、fsync、rename 和覆盖前备份。损坏数据拒绝写入。
- `service.ts`：所有操作进入 `controlled(ctx)`；写入锁内再次鉴权；来源只能调用 MemoryService。客户端不能提供 owner。回忆录和惊喜按账号哈希隔离；编辑和删除验证 revision，删除还要 confirmed。
- `POST /api/v4` 最大 1MB，防止长中文章节无法编辑；其他 API 原有限额不变。
- 旧修改包状态以 Schema 默认值兼容：旧书没有结构化章节时仍能编辑 Markdown 并导出。不会自动重建、覆盖或迁移真实文件。

## 回忆录与 PDF

从 1–12 条选择且符合日期/地点/标签筛选的回忆生成章节。章节保留 Memory ID、原始日期、地点、来源 revision 和照片。最多每章 20000 字、每册 40 张不同照片。章节可排序、编辑、恢复原文、AI 重新摘录。重新生成仅返回候选章节，须另行保存；来源已改变时要求重新生成书册，避免把新事实混进旧版本快照。

AI 采用保守的抽取式叙事：模型选择顺序和原文连续片段，服务端验证每个来源恰好一次、引用确为发送片段的子串；标题、日期和地点由服务器取原记录。没有事实来源时拒绝生成，不能让模型自由补写人物、对话或经历。手动修改内容标为作者草稿，不能自动写回原始 Love Memory。

`pdf.ts` 使用新增运行依赖 `playwright-core` 和服务器已安装的 Chromium/Edge。受保护 POST `/api/v4/books/:id/pdf` 验证 owner、revision，服务器读取已鉴权照片并压缩为内存 data URL。没有临时 PDF 落盘、不发照片到 DeepSeek、不复制到 public。HTML 全部转义、禁用 JavaScript、阻断浏览器网络、CSP 禁止外部资源。一个进程最多同时排版一份，启动/排版都有超时。返回前再次鉴权和检查版本。

提供「星夜情书」「暖纸纪念册」，包含封面、日期区间、章节标题、原文、照片、来源和页码。导出完整已保存草稿，未保存时按钮禁用。服务器需要中文字体；Linux 部署路径见部署文档。私人照片被书册引用时图库删除会拒绝。

## Agent 任务与惊喜策划

`src/lib/agent/companion.ts` 是 V3 的有界任务扩展，复用同一个 DeepSeek Provider（默认 deepseek-flash）、requireConsent、sharedRecord、reserveBudget。任务白名单是 book/surprise，没有文件工具、HTTP 工具或写工具，不创建第二套 Provider 或独立 Agent 框架。

调用前后验证双方启用与当前来源 revision；secret 等记录不可外发。每任务一次 complete，Provider 的既有有限重试不变；30 秒任务期限、14000 字节输入、30000 已报告 token 上限。与 V3 私人 AI 共用每小时 6 / 每日 30 次额度。照片、邮箱、owner 不发送；日志不写提示词或结果。

惊喜输入预算/日期/城市/可用分钟/偏好/来源，结果包含主题、活动分钟、费用、准备清单、邀约文案、需人工核实项和经过逐字校验的历史引用。超预算或超时长拒绝。未来建议不是已经发生的事实，具体商家价格等不作真实性承诺。用户点生成保存的是私人草稿；不会采购、预订、付款、发消息或修改回忆。AI 故障保留已有内容，本地非 AI 草稿仍可用。

## 胶囊与照片

锁定日期按 Asia/Shanghai 日历日计算。正文和附件 ID/alt 在锁定时均不返回；到期后双方登录可查看，删除限创建者，要求 revision + confirmed。

从已授权的共享私人照片库选择最多 8 张，复制为新随机 ID 到 `private/sealed/`。该副本不在图库列表，也不能通过 `/api/uploads/:id` 获取。专用 `/api/v4/capsules/:id/photos/:photo` 逐次鉴权、判断日期和所属关系，返回 no-store。原图库照片本来属于共享空间，不承诺把原照片变为秘密；UI 明确告知这一点。

删除时备份整个状态，封存副本保留用于恢复，不会再经 API 提供。失败写入可能留下无法访问的孤立副本；不自动删除，管理员离线核对备份后清理。宿主机管理员可读取磁盘，不宣称防御已控制服务器或回拨系统时钟的管理员。

## 主动提醒

`reminders.ts` 复用私人纪念日 Schema 与 V1 nextAnniversary；每成员可选 IANA 时区及 30/7/1/0 天。到期判断是确定性日期计算，不交给模型。

常在线 Linux 单实例主机使用 systemd 每 15 分钟调用本机受任务凭据保护的 POST `/api/internal/reminders`。该凭据与用户会话独立，至少 32 字节随机数（64 位十六进制），只允许提醒任务，不能访问 MemoryService。普通用户 Cookie 不能代替任务凭据；demo 模式禁用。计时器、Node 脚本及环境文件由管理员部署，任务不依赖打开网页。

一次事务中计算、去重并写站内通知；key 绑定 owner/纪念日 ID/本次日期/提前天数。并发、重试与重启不会重复写入。停机后依据 lastRun 补偿，最多回补 366 天且不早于该成员启用日；通知记录保留 400 天、上限 10000，超限整笔失败。超过一年离线需要管理员核查，不承诺无限追溯。更改时区可能调整未来触发时刻，同一 occurrence 不重复。通知支持已读；界面显示最近任务运行时间，不将近期事件列表误当成任务执行记录。

当前本地电脑不是可靠调度宿主机，尚未部署常在线服务。脚本和逻辑通过本地测试不等于生产任务已启用。站内通知落盘没有外部消息副作用；外部通道接口始终拒绝发送，详见部署文档。

## 往年今日与游戏

往年今日按上海相同月日查询历史记录，复用受保护照片和原始详情；只有明确确认才生成本地分享文件，不自动上传或发送。秘密/禁止第三方记录不进入此聚合与题库。

游戏仅基于 MemoryService 返回的普通回忆，四种模式（地点、时间、混合问答、默契比较），同屏交接给双方独立选择，最后揭晓双人得分与一致率，可重玩。不会查询惊喜或胶囊存储。属于情侣休闲游戏，不是防作弊考试；普通回忆本来双方可见。暂不提供跨设备实时对战。
